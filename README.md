# uncle-rag

ระบบถาม-ตอบจากไฟล์ PDF แบบ RAG อยู่ในไฟล์ Python ไฟล์เดียว รองรับเอกสารภาษาไทยและอังกฤษ ตอบพร้อมอ้างอิงเลขหน้าที่ตรวจสอบย้อนกลับได้

repo นี้มีสองเวอร์ชัน ใช้แนวคิดเดียวกันแต่ออกแบบมาคนละโจทย์ รันพร้อมกันได้เพราะใช้คนละพอร์ตและคนละคลังข้อมูล

## นี่คืออะไร

uncle-rag คือระบบ RAG (Retrieval-Augmented Generation) ที่ย่อทั้งกระบวนการให้เหลือไฟล์ Python ไฟล์เดียว หลักการคือแทนที่จะเทรนโมเดลใหม่ให้รู้จักเอกสารของคุณ เราหาวิธีหยิบเฉพาะส่วนที่เกี่ยวข้องส่งให้มันอ่านตอนถามแทน เมื่ออัปโหลด PDF เข้าไป โปรแกรมจะดึงข้อความออกมาทีละหน้า หั่นเป็นก้อนเล็ก ๆ ที่เหลื่อมกันเพื่อไม่ให้เนื้อหาตรงรอยต่อหาย แล้วแปลงแต่ละก้อนเป็นเวกเตอร์ตัวเลขที่แทนความหมายของข้อความนั้นเก็บไว้ พอคุณพิมพ์คำถาม ระบบจะแปลงคำถามเป็นเวกเตอร์ด้วยวิธีเดียวกัน หาก้อนที่ความหมายอยู่ใกล้ที่สุดไม่กี่ก้อน แล้วส่งเฉพาะก้อนเหล่านั้นไปให้โมเดลภาษาอ่านพร้อมคำถาม โมเดลจึงตอบจากเอกสารของคุณจริง ๆ ไม่ใช่เดาจากความรู้ทั่วไป และเพราะรู้ว่าแต่ละก้อนมาจากหน้าไหน ทุกคำตอบจึงมีเลขหน้ากำกับให้ย้อนกลับไปตรวจต้นฉบับได้ทันที ทั้งหมดนี้ไม่ต้องเทรนอะไรเลย อัปโหลดไฟล์ใหม่แล้วถามได้ทันที

> **อยากเรียนแบบเป็นระบบตั้งแต่ต้นจนถึงระดับใช้งานจริง**
>
> โปรเจกต์นี้เป็นเพียงชิ้นส่วนเดียวของภาพใหญ่ ถ้าอยากสร้าง AI Agent ที่จำผู้ใช้ได้ ค้นความรู้จากเอกสารเป็น เรียก API ได้ และทำงานร่วมกันหลายตัว ดูคอร์ส **[Super Memory AI Agent with Hermes & RAG](https://uncle-engineer.com/course/super-memory-ai-agent-hermes-rag/) https://uncle-engineer.com/course/super-memory-ai-agent-hermes-rag/** ของ Uncle Engineer เรียนออนไลน์ 10 สัปดาห์ รายละเอียดอยู่ท้ายไฟล์นี้

| | `uncle-rag.py` | `uncle-rag-local.py` |
|---|---|---|
| แนวทาง | ยิง API อย่างเดียว | เลือก provider ให้อัตโนมัติ |
| ต้องมีคีย์ไหม | ต้องมี | ไม่ต้อง รันได้ทันที |
| ทำงานออฟไลน์ | ไม่ได้ | ได้ |
| เอกสารออกนอกเครื่อง | ออก | เลือกได้ว่าไม่ให้ออก |
| ตั้งค่าที่ | ไฟล์ `.env` | แก้ค่าคงที่หัวไฟล์ |
| เก็บคลังที่ | `rag.db` (SQLite) | `rag_store.pkl` (pickle) |
| พอร์ต | 5000 | 5001 |

**เลือกยังไง**

- อยากได้คุณภาพคำตอบสูงสุดและไม่ซีเรียสเรื่องข้อมูลออกนอกเครื่อง ใช้ `uncle-rag.py`
- เอกสารเป็นความลับ หรืออยู่ที่ไม่มีเน็ต หรืออยากลองก่อนโดยไม่ต้องสมัครอะไร ใช้ `uncle-rag-local.py`
- ใช้สอนหรือสาธิต ใช้ `uncle-rag-local.py` เพราะผู้เรียนรันได้เลยโดยไม่ต้องมีคีย์ และหน้าเว็บแสดงความคืบหน้าทีละขั้นให้เห็นว่า RAG ทำงานอย่างไร

## ติดตั้ง

ต้องใช้ Python 3.9 ขึ้นไป ทั้งสองเวอร์ชันใช้ชุดเดียวกัน

```bash
pip install flask pypdf numpy requests
```

แนะนำให้ลงเพิ่มอีกตัว เพื่อให้การค้นหาเป็นแบบเข้าใจความหมายจริง

```bash
pip install sentence-transformers
```

ครั้งแรกจะดาวน์โหลดโมเดลราว 500 MB แล้วใช้ออฟไลน์ได้ตลอด

# เวอร์ชัน 1 — `uncle-rag.py`

ยิง OpenRouter คีย์เดียวสำหรับทั้งการสร้างเวกเตอร์และการถามโมเดล

## ตั้งค่า

```bash
cp .env.example .env
```

| ตัวแปร | ค่าตั้งต้น | ความหมาย |
|---|---|---|
| `OPENROUTER_API_KEY` | — | คีย์จาก openrouter.ai/keys จำเป็นต้องมี |
| `CHAT_MODEL` | `anthropic/claude-sonnet-5` | โมเดลที่ใช้ตอบ ดู slug ที่ openrouter.ai/models |
| `EMBED_BACKEND` | `openrouter` | `openrouter` หรือ `local` |
| `EMBED_MODEL` | `openai/text-embedding-3-large` | โมเดลสร้างเวกเตอร์ |
| `RAG_DB` | `rag.db` | ที่เก็บ index |
| `CHUNK_SIZE` | `900` | จำนวนตัวอักษรต่อหนึ่งก้อน |
| `CHUNK_OVERLAP` | `180` | ตัวอักษรที่ให้แต่ละก้อนซ้อนกัน |
| `TOP_K` | `6` | ส่งกี่ก้อนเข้า prompt |
| `MIN_SCORE` | `0.25` | คะแนน cosine ต่ำกว่านี้ตัดทิ้ง |
| `MAX_TOKENS` | `2048` | ความยาวคำตอบสูงสุด |

ตัวแปรที่ตั้งไว้ใน shell หรือใน container อยู่แล้วจะชนะค่าใน `.env` เสมอ ออกแบบไว้แบบนี้เพื่อไม่ให้ `.env` ที่ค้างอยู่ใน image ทับคีย์จริงตอน deploy

## รัน

```bash
python uncle-rag.py
```

เปิด http://127.0.0.1:5000

ตอนสตาร์ทจะพิมพ์สถานะออกมาให้ตรวจว่าอ่านค่าถูกไหม

```
env file: /home/loong/uncle-rag/.env
key: sk-or-v1-a…9f2c
DB=rag.db  embed=openrouter:openai/text-embedding-3-large  chat=anthropic/claude-sonnet-5
chunks in index: 128  (index model: openai/text-embedding-3-large)
```

คำสั่งอื่น

```bash
python uncle-rag.py --env /path/to/.env    # ระบุไฟล์ .env เอง
python uncle-rag.py --list-embed-models    # ดูรายชื่อ embedding model ที่ใช้ได้จริงตอนนี้
```

# เวอร์ชัน 2 — `uncle-rag-local.py`

ไม่ต้องตั้งค่าอะไรก็รันได้ ตัวโปรแกรมจะสำรวจว่าเครื่องมีอะไรให้ใช้บ้างแล้วเลือกให้เอง

## รัน

```bash
python uncle-rag-local.py
```

เปิด http://127.0.0.1:5001

ตอนสตาร์ทจะบอกว่าเลือกอะไรไปใช้

```
==============================================================
  RAG Chat  ·  ถาม-ตอบจากไฟล์ PDF
==============================================================
  ค้นหา  : Semantic — sentence-transformers · multilingual-e5-small
  ผู้ตอบ : qwen2.5:7b
  คลัง   : 2 เอกสาร · 143 chunk

  เปิด   : http://127.0.0.1:5001
==============================================================
```

## ระบบเลือกให้อย่างไร

**ฝั่งค้นหา** ไล่จากดีที่สุดลงมา

1. `sentence-transformers` ถ้าลงไว้ — คุณภาพดีที่สุด ทำงานออฟไลน์
2. Ollama ถ้าเปิดอยู่และมีโมเดล `bge-m3`
3. ตัวสำรอง built-in ที่ใช้ character 3-gram กับ hashing — ไม่ต้องลงอะไรเพิ่ม ใช้กับภาษาไทยได้โดยไม่ต้องตัดคำ แต่เป็นการจับคู่ตัวอักษรที่ซ้ำกัน ไม่ได้เข้าใจความหมาย ถามด้วยคำที่ไม่ตรงกับในเอกสารจะหาไม่เจอ เหมาะสำหรับลองให้เห็นภาพรวมของ RAG มากกว่าใช้งานจริง

**ฝั่งตอบคำถาม** ไล่ตามลำดับ

1. `ANTHROPIC_API_KEY` ถ้ามีใน environment
2. `OPENAI_API_KEY` ถ้ามี
3. Ollama ถ้าเปิดอยู่ — ถ้าไม่มีรุ่น `qwen2.5:7b` จะหยิบรุ่นอื่นที่ติดตั้งไว้มาใช้แทนโดยอัตโนมัติ
4. ไม่มีเลย — ยังใช้ได้ แต่จะแสดงเฉพาะเนื้อหาที่ค้นเจอ ไม่มีการเรียบเรียงคำตอบ

ถ้าระบบต้องถอยไปใช้ตัวสำรอง จะขึ้นข้อความ `[!]` บอกเหตุผลและวิธีแก้ตอนสตาร์ท

## ใช้แบบออฟไลน์เต็มรูปแบบ

```bash
pip install sentence-transformers
ollama pull qwen2.5:7b
python uncle-rag-local.py
```

เท่านี้ทั้งการค้นและการตอบอยู่ในเครื่องทั้งหมด เอกสารไม่ออกไปไหนเลย

ถ้าอยากให้ Ollama ทำ embedding ด้วย ให้ `ollama pull bge-m3` แล้วแก้ `EMBED_PROVIDER = "ollama"` ที่หัวไฟล์

## ตั้งค่า

เวอร์ชันนี้แก้ค่าคงที่ที่หัวไฟล์ตรง ๆ ในหัวข้อ `1) ตั้งค่า`

| ค่า | ค่าตั้งต้น | ความหมาย |
|---|---|---|
| `CHUNK_SIZE` | `900` | จำนวนตัวอักษรต่อหนึ่งก้อน |
| `CHUNK_OVERLAP` | `150` | ตัวอักษรที่ให้แต่ละก้อนซ้อนกัน |
| `TOP_K` | `4` | ส่งกี่ก้อนเข้า prompt ปรับได้จากแถบเลื่อนในหน้าเว็บด้วย |
| `EMBED_PROVIDER` | `auto` | `auto` `st` `ollama` `simple` |
| `LLM_PROVIDER` | `auto` | `auto` `anthropic` `openai` `ollama` `none` |
| `ST_MODEL` | `intfloat/multilingual-e5-small` | โมเดล sentence-transformers |
| `OLLAMA_LLM` | `qwen2.5:7b` | โมเดลตอบคำถามใน Ollama |
| `OLLAMA_EMBED` | `bge-m3` | โมเดล embedding ใน Ollama |
| `STORE_FILE` | `rag_store.pkl` | ที่เก็บคลัง |
| `HOST`, `PORT` | `127.0.0.1`, `5001` | ที่อยู่ของเซิร์ฟเวอร์ |

ส่วนคีย์และปลายทางอ่านจาก environment ได้แก่ `ANTHROPIC_API_KEY` `OPENAI_API_KEY` `OPENAI_BASE_URL` `OPENAI_MODEL` `ANTHROPIC_MODEL` `OLLAMA_URL`

**ข้อควรรู้** เวอร์ชันนี้ไม่ได้อ่านไฟล์ `.env` ต้อง export เอาเอง

```bash
export ANTHROPIC_API_KEY=sk-ant-...
python uncle-rag-local.py
```

หรือถ้าอยากใช้ `.env` ร่วมกันทั้งสองไฟล์ ให้คัดลอกฟังก์ชัน `load_dotenv()` จาก `uncle-rag.py` มาวางไว้เหนือหัวข้อตั้งค่า แล้วเรียกใช้หนึ่งบรรทัด

## เคล็ดลับ ใช้คีย์ OpenRouter กับเวอร์ชันนี้

ช่องทาง OpenAI ในไฟล์นี้เป็นมาตรฐานเดียวกับที่ OpenRouter ใช้ จึงชี้ไปที่ OpenRouter ได้เลย ใช้คีย์ใบเดียวกับเวอร์ชันแรก

```bash
export OPENAI_API_KEY=sk-or-v1-...
export OPENAI_BASE_URL=https://openrouter.ai/api/v1
export OPENAI_MODEL=anthropic/claude-sonnet-5
python uncle-rag-local.py
```

ได้เป็นการค้นในเครื่องแต่ให้โมเดลบนคลาวด์ตอบ ซึ่งเป็นจุดสมดุลที่ดีเวลาไม่อยากส่งเอกสารทั้งฉบับออกไปสร้างเวกเตอร์ แต่ยอมส่งเฉพาะส่วนที่ค้นเจอไปให้โมเดลอ่าน

## วิธีใช้งาน

ใช้เหมือนกันทั้งสองเวอร์ชัน

ลากไฟล์ PDF มาวาง หรือคลิกเพื่อเลือกไฟล์ รอจนขึ้นว่าเพิ่มไฟล์เรียบร้อย แล้วพิมพ์คำถาม กด Enter เพื่อส่ง กด Shift+Enter เพื่อขึ้นบรรทัดใหม่

`uncle-rag.py` แสดงอ้างอิงเป็นตัวเลข `[1] [2]` ท้ายประโยค กางดูข้อความต้นฉบับได้จากรายการด้านล่างคำตอบ

`uncle-rag-local.py` ให้โมเดลเขียนอ้างอิงเป็น `(หน้า 42)` ในเนื้อความ และแสดงผลการค้นพร้อมคะแนนไว้ก่อนที่คำตอบจะเริ่มพิมพ์ ระหว่างอัปโหลดจะเห็นความคืบหน้าทีละขั้น อ่าน ตัด สร้างเวกเตอร์ เก็บ ทำให้เห็นว่าเวลาส่วนใหญ่หมดไปกับขั้นไหน

ประวัติการสนทนาเก็บอยู่ในเบราว์เซอร์ กด refresh คือหายหมด แต่เอกสารยังอยู่

## หลักการทำงาน

ทั้งสองไฟล์ใช้ pipeline เดียวกัน

**ตอนอัปโหลด** ดึงข้อความจาก PDF ทีละหน้าพร้อมจำว่าตำแหน่งตัวอักษรช่วงไหนคือหน้าไหน ต่อทุกหน้าเป็นข้อความเดียวแล้วตัดเป็นก้อนราว 900 ตัวอักษรที่ซ้อนกัน แปลงแต่ละก้อนเป็นเวกเตอร์ แล้วเก็บลงคลัง

การตัดด้วยจำนวนตัวอักษรเป็นเรื่องสำคัญสำหรับเอกสารไทย เพราะภาษาไทยไม่มีช่องว่างระหว่างคำ ถ้าใช้วิธีตัดตามคำแบบภาษาอังกฤษ ทั้งย่อหน้าจะกลายเป็นก้อนเดียว

**ตอนถาม** แปลงคำถามเป็นเวกเตอร์ แล้วคูณกับเมทริกซ์ของทุกก้อนในครั้งเดียว เวกเตอร์ทุกตัวถูกทำให้ยาวเท่ากับหนึ่งตั้งแต่ตอนบันทึก ผลคูณจึงเป็นค่า cosine โดยตรง จากหนึ่งหมื่นก้อนใช้เวลาราว 20 มิลลิวินาที เอาก้อนที่ใกล้เคียงที่สุดไปประกอบเป็น prompt ให้โมเดลอ่านแล้วเรียบเรียงคำตอบ

การสร้างเวกเตอร์ของเอกสารเกิดขึ้นครั้งเดียวตอนอัปโหลด ถามกี่รอบก็ไม่ต้องทำใหม่

**จุดที่ต่างกันในรายละเอียด**

`uncle-rag.py` มีเกณฑ์คะแนนขั้นต่ำ ถ้าไม่มีก้อนไหนถึงเกณฑ์จะตอบว่าไม่พบเนื้อหาโดยไม่เรียกโมเดล ส่วน `uncle-rag-local.py` ส่งก้อนที่ใกล้ที่สุดไปเสมอตามจำนวนที่ตั้งไว้ แม้คะแนนจะต่ำ จึงควรดูคะแนนในรายการผลค้นประกอบด้วยว่าคำตอบน่าเชื่อถือแค่ไหน

## API

**`uncle-rag.py`**

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| `GET` | `/api/status` | รายชื่อเอกสาร จำนวนก้อน โมเดลที่ใช้ |
| `POST` | `/api/upload` | อัปโหลด PDF แบบ multipart ฟิลด์ `file` |
| `DELETE` | `/api/documents/<id>` | ลบเอกสาร |
| `POST` | `/api/search` | ค้นอย่างเดียว ไม่เรียกโมเดล |
| `POST` | `/api/ask` | ถามและรับคำตอบแบบสตรีม |

**`uncle-rag-local.py`**

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| `GET` | `/api/status` | สถิติคลัง |
| `POST` | `/api/upload` | อัปโหลด PDF และรับความคืบหน้าเป็นสตรีม |
| `POST` | `/api/ask` | ถามและรับคำตอบแบบสตรีม |
| `POST` | `/api/remove` | ลบเอกสาร ส่ง `{"name": "ชื่อไฟล์"}` |

## ปรับคุณภาพคำตอบ

เวลาคำตอบไม่ดี คำถามแรกที่ต้องตอบให้ได้คือ ระบบหาก้อนที่ถูกต้องเจอหรือเปล่า ดูได้จากรายการผลค้นในหน้าเว็บ หรือใน `uncle-rag.py` ใช้ `/api/search` ที่ค้นอย่างเดียวไม่เสียค่าโมเดล

```bash
curl -s localhost:5000/api/search -H 'Content-Type: application/json' \
  -d '{"question":"ความเร็วตัดของ 4140","k":10}' | python -m json.tool
```

- ก้อนที่ต้องการ **ไม่โผล่มาเลย** ปัญหาอยู่ที่การค้น ลองเพิ่ม `TOP_K` ลด `MIN_SCORE` หรือเปลี่ยนโมเดล embedding ถ้าใช้เวอร์ชัน local ที่ตกไปใช้ตัวสำรอง built-in อยู่ ให้ลง `sentence-transformers` ก่อนเป็นอันดับแรก
- ก้อนที่ต้องการ **โผล่มาแต่เนื้อหาขาดกลางคัน** ปัญหาอยู่ที่การตัด ลองเพิ่ม `CHUNK_SIZE` หรือ `CHUNK_OVERLAP`
- ก้อนที่ต้องการ **โผล่มาครบแต่ตอบผิด** ปัญหาอยู่ที่โมเดล ลองเปลี่ยนเป็นรุ่นที่ใหญ่ขึ้น

**สำคัญ** ถ้าเปลี่ยนโมเดล embedding ต้องสร้างคลังใหม่ทั้งหมด เพราะเวกเตอร์คนละโมเดลอยู่คนละปริภูมิ เอามาเทียบกันจะได้ตัวเลขที่ดูสมเหตุสมผลแต่ผลลัพธ์มั่ว `uncle-rag.py` จะปฏิเสธการอัปโหลดพร้อมบอกเหตุผล ส่วน `uncle-rag-local.py` จะล้างคลังให้เองแล้วเริ่มใหม่

ส่วน `CHUNK_SIZE` กับ `TOP_K` เปลี่ยนแล้วมีผลกับไฟล์ที่อัปโหลดใหม่เท่านั้น ของเก่าไม่เปลี่ยนตาม

## ปัญหาที่พบบ่อย

**ขึ้นว่าอ่านข้อความจาก PDF ไม่ได้**

เป็น PDF สแกนที่มีแต่ภาพ ต้องทำ OCR ก่อน

```bash
ocrmypdf -l tha+eng input.pdf output.pdf
```

**ค้นแล้วได้ผลไม่เกี่ยวเลย (เวอร์ชัน local)**

ดูบรรทัด `ค้นหา` ตอนสตาร์ท ถ้าขึ้นว่า `พื้นฐาน` แสดงว่ากำลังใช้ตัวสำรองที่จับคู่แค่ตัวอักษร ไม่เข้าใจความหมาย แก้ด้วย `pip install sentence-transformers` แล้วรันใหม่ คลังเดิมจะถูกล้างอัตโนมัติเพราะเปลี่ยนโมเดล ต้องอัปโหลดใหม่

**ขึ้นว่า Ollama ยังไม่มีโมเดล**

```bash
ollama pull qwen2.5:7b      # สำหรับตอบคำถาม
ollama pull bge-m3          # สำหรับ embedding ถ้าจะใช้ทางนี้
```

**ตัวหนังสือไทยเพี้ยนเป็น `Ã Â¸`**

เกิดกับ `uncle-rag.py` รุ่นเก่า สาเหตุคือ OpenRouter ไม่ระบุ charset มาในส่วนหัวของ SSE ทำให้ requests ถอยไปใช้ ISO-8859-1 ตามข้อกำหนดเก่าของ HTTP แก้แล้วในรุ่นปัจจุบัน ถ้ายังเจออยู่ให้เช็คว่ามีบรรทัด `r.encoding = "utf-8"` ในฟังก์ชัน `stream_chat`

**401 หรือ No auth credentials found**

คีย์ไม่ถูกอ่าน เวอร์ชันแรกดูบรรทัด `env file:` ตอนสตาร์ทว่าชี้ไปไฟล์ที่ถูกต้องไหม เวอร์ชัน local ต้อง export คีย์เอง เพราะไม่ได้อ่าน `.env`

**402 หรือ Insufficient credits**

เครดิต OpenRouter หมด เติมที่หน้า credits

**429 หรือรอนาน**

ชน rate limit `uncle-rag.py` retry ให้เองสูงสุด 4 ครั้ง ถ้ายังไม่ผ่านให้ลดขนาดไฟล์ที่อัปโหลดต่อครั้ง

**ตารางในเอกสารอ่านออกมาแล้วคอลัมน์เละ**

เป็นข้อจำกัดของการดึงข้อความจาก PDF ถ้าเอกสารมีตารางสเปกเยอะ ควรใช้ `pdfplumber.extract_tables()` แปลงเป็นตาราง markdown ก่อนเข้าขั้นตอนตัดก้อน

## ข้อจำกัดที่ควรรู้

- ค้นด้วยเวกเตอร์อย่างเดียว ยังไม่มีการค้นแบบคำต่อคำ ถ้าต้องค้นรหัสชิ้นงานหรือหมายเลขพาร์ตที่ต้องตรงเป๊ะ ควรเติม BM25 แล้วรวมคะแนนสองแบบเข้าด้วยกัน
- คลังอยู่ในหน่วยความจำทั้งก้อน เหมาะกับหลักหมื่นก้อน เกินจากนั้นควรย้ายไป FAISS หรือ pgvector
- `rag_store.pkl` เป็นไฟล์ pickle อย่าเปิดไฟล์ที่รับมาจากคนอื่น เพราะ pickle รันโค้ดได้ตอนโหลด
- ทั้งสองไฟล์เก็บข้อความเต็มของเอกสารไว้ในคลัง อย่า commit เข้า git

```bash
echo ".env" >> .gitignore
echo "rag.db" >> .gitignore
echo "rag_store.pkl" >> .gitignore
```

## นำขึ้นเซิร์ฟเวอร์

เซิร์ฟเวอร์ที่มากับ Flask ใช้สำหรับพัฒนาเท่านั้น ถ้าจะให้คนอื่นใช้ด้วย

```bash
pip install gunicorn
gunicorn -w 1 --threads 8 -t 300 -b 0.0.0.0:8000 uncle-rag:app
```

ต้องใช้ worker เดียวเท่านั้น เพราะแต่ละ worker ถือสำเนาคลังของตัวเองในหน่วยความจำ ถ้าเปิดหลาย worker แล้วมีคนอัปโหลดไฟล์ worker อื่นจะมองไม่เห็นจนกว่าจะรีสตาร์ท อาการจะออกมาเป็นแบบสุ่มคือบางครั้งค้นเจอบางครั้งไม่เจอ ขึ้นกับว่า request ตกไปที่ worker ไหน ให้เพิ่มจำนวน thread แทน และตั้ง timeout ยาวเพราะคำตอบเป็นการสตรีมที่กินเวลา

ถ้าวางหลัง nginx ต้องปิด buffering ไม่งั้นคำตอบจะไม่ทยอยออกมาแต่จะโผล่ทีเดียวตอนจบ

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_buffering off;
    proxy_read_timeout 300s;
}
```
