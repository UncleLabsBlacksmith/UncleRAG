# uncle-rag

ระบบถาม-ตอบจากไฟล์ PDF แบบ RAG อยู่ในไฟล์ Python ไฟล์เดียว รองรับเอกสารภาษาไทยและอังกฤษ ตอบพร้อมอ้างอิงเลขหน้าที่ตรวจสอบย้อนกลับได้

ใช้ OpenRouter คีย์เดียวสำหรับทั้งการสร้างเวกเตอร์และการถามโมเดล

---

## ทำอะไรได้บ้าง

- อัปโหลด PDF หลายไฟล์ ค้นข้ามไฟล์ได้พร้อมกัน
- ตอบแบบสตรีมทีละคำ ไม่ต้องรอจนจบ
- ทุกคำตอบมีเลขอ้างอิง `[1] [2]` กดดูได้ว่าข้อความต้นทางอยู่ไฟล์ไหน หน้าไหน คะแนนความใกล้เคียงเท่าไหร่
- เก็บ index ลง SQLite ปิดเครื่องแล้วไม่ต้องประมวลผลใหม่
- สลับไปสร้างเวกเตอร์บนเครื่องตัวเองได้ ถ้าเอกสารเป็นความลับ

---

## ติดตั้ง

ต้องใช้ Python 3.9 ขึ้นไป

```bash
pip install flask pypdf numpy requests
```

ถ้าจะสร้างเวกเตอร์บนเครื่องแทนการยิง API ให้ลงเพิ่ม

```bash
pip install sentence-transformers
```

## ตั้งค่า

คัดลอกไฟล์ตัวอย่างแล้วใส่คีย์จริง

```bash
cp .env.example .env
```

| ตัวแปร | ค่าตั้งต้น | ความหมาย |
|---|---|---|
| `OPENROUTER_API_KEY` | — | คีย์จาก openrouter.ai/keys จำเป็นต้องมี |
| `CHAT_MODEL` | `anthropic/claude-sonnet-5` | โมเดลที่ใช้ตอบ ดู slug ที่ openrouter.ai/models |
| `EMBED_BACKEND` | `openrouter` | `openrouter` หรือ `local` |
| `EMBED_MODEL` | `openai/text-embedding-3-large` | โมเดลสร้างเวกเตอร์ |
| `RAG_DB` | `rag.db` | ที่เก็บ index |
| `CHUNK_SIZE` | `900` | จำนวนตัวอักษรต่อหนึ่งก้อน |
| `CHUNK_OVERLAP` | `180` | ตัวอักษรที่ให้แต่ละก้อนซ้อนกัน |
| `TOP_K` | `6` | ส่งกี่ก้อนเข้า prompt |
| `MIN_SCORE` | `0.25` | คะแนน cosine ต่ำกว่านี้ตัดทิ้ง |
| `MAX_TOKENS` | `2048` | ความยาวคำตอบสูงสุด |

ตัวแปรที่ตั้งไว้ใน shell หรือใน container อยู่แล้วจะชนะค่าใน `.env` เสมอ ออกแบบไว้แบบนี้เพื่อไม่ให้ `.env` ที่ค้างอยู่ใน image ทับคีย์จริงตอน deploy

**อย่าลืม**

```bash
echo ".env" >> .gitignore
echo "rag.db" >> .gitignore
```

`rag.db` ต้องใส่ด้วย เพราะข้างในเก็บข้อความเต็มของทุกเอกสารที่อัปโหลด

## รัน

```bash
python uncle-rag.py
```

เปิด http://127.0.0.1:5000

ตอนสตาร์ทจะพิมพ์สถานะออกมาให้ตรวจว่าอ่านค่าถูกไหม

```
env file: /home/loong/uncle-rag/.env
key: sk-or-v1-a…9f2c
DB=rag.db  embed=openrouter:openai/text-embedding-3-large  chat=anthropic/claude-sonnet-5

```

## วิธีใช้งาน

ลากไฟล์ PDF มาวางในกรอบด้านซ้าย หรือคลิกเพื่อเลือกไฟล์ รอจนขึ้นว่าเพิ่มไฟล์แล้วใช้เวลากี่วินาที แล้วพิมพ์คำถามในช่องล่างขวา กด Enter เพื่อส่ง กด Shift+Enter เพื่อขึ้นบรรทัดใหม่

คำตอบจะมีเลข `[1] [2]` กำกับ ด้านล่างมีรายการแหล่งอ้างอิงพร้อมคะแนน กดสามเหลี่ยมเพื่อกางดูข้อความต้นฉบับที่ระบบหยิบมาใช้จริง

กดกากบาทข้างชื่อไฟล์เพื่อลบเอกสารออกจาก index

ประวัติการสนทนาเก็บอยู่ในเบราว์เซอร์ กด refresh คือหายหมด แต่เอกสารยังอยู่ ระบบส่งบทสนทนาย้อนหลังไปกับคำถามแค่ 6 เทิร์นล่าสุดเพื่อคุมขนาดและค่าใช้จ่ายของ prompt

## หลักการทำงาน

**ตอนอัปโหลด** ดึงข้อความจาก PDF ทีละหน้าพร้อมจำว่าตำแหน่งตัวอักษรช่วงไหนคือหน้าไหน จากนั้นต่อทุกหน้าเป็นข้อความเดียวแล้วตัดเป็นก้อนขนาด 900 ตัวอักษร ซ้อนกัน 180 ตัวอักษร ส่งไปสร้างเวกเตอร์ครั้งละ 64 ก้อน แล้วเก็บลง SQLite พร้อมโหลดขึ้นหน่วยความจำเป็นเมทริกซ์ก้อนเดียว

การตัดด้วยจำนวนตัวอักษรเป็นเรื่องสำคัญสำหรับเอกสารไทย เพราะภาษาไทยไม่มีช่องว่างระหว่างคำ ถ้าใช้วิธีตัดตามคำแบบภาษาอังกฤษ ทั้งย่อหน้าจะกลายเป็นก้อนเดียว

**ตอนถาม** แปลงคำถามเป็นเวกเตอร์ แล้วคูณกับเมทริกซ์ทั้งก้อนในครั้งเดียว เวกเตอร์ทุกตัวถูกทำให้ยาวเท่ากับหนึ่งตั้งแต่ตอนบันทึก ผลคูณจึงเป็นค่า cosine โดยตรง จากหนึ่งหมื่นก้อนใช้เวลาราว 20 มิลลิวินาที เอา 6 อันดับแรกที่คะแนนถึงเกณฑ์ไปประกอบเป็น prompt ถ้ากรองแล้วไม่เหลืออะไรเลย ระบบตอบว่าไม่พบเนื้อหาโดยไม่เรียกโมเดล ประหยัดเงินและกันการเดา

การสร้างเวกเตอร์ของเอกสารเกิดขึ้นครั้งเดียวตอนอัปโหลด ถามกี่รอบก็ไม่เสียค่า embedding ซ้ำ

## API

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| `GET` | `/api/status` | รายชื่อเอกสาร จำนวนก้อน โมเดลที่ใช้ |
| `POST` | `/api/upload` | อัปโหลด PDF แบบ multipart ฟิลด์ชื่อ `file` |
| `DELETE` | `/api/documents/<id>` | ลบเอกสาร |
| `POST` | `/api/search` | ค้นอย่างเดียว ไม่เรียกโมเดล |
| `POST` | `/api/ask` | ถามและรับคำตอบแบบสตรีม |

## ปรับคุณภาพคำตอบ

เวลาคำตอบไม่ดี คำถามแรกที่ต้องตอบให้ได้คือ ระบบหาก้อนที่ถูกต้องเจอหรือเปล่า ใช้ `/api/search` ดูผลการค้นดิบ ๆ โดยไม่เสียเงินค่าโมเดล

```bash
curl -s localhost:5000/api/search -H 'Content-Type: application/json' \
  -d '{"question":"ความเร็วตัดของ 4140","k":10}' | python -m json.tool
```

- ถ้าก้อนที่ต้องการ **ไม่โผล่มาเลย** ปัญหาอยู่ที่การค้น ลองลด `MIN_SCORE`, เพิ่ม `TOP_K` หรือเปลี่ยน `EMBED_MODEL`
- ถ้าก้อนที่ต้องการ **โผล่มาแต่เนื้อหาขาดกลางคัน** ปัญหาอยู่ที่การตัด ลองเพิ่ม `CHUNK_SIZE` หรือ `CHUNK_OVERLAP`
- ถ้าก้อนที่ต้องการ **โผล่มาครบแต่โมเดลตอบผิด** ปัญหาอยู่ที่ prompt หรือโมเดล ลองเปลี่ยน `CHAT_MODEL`

**สำคัญ** ถ้าเปลี่ยน `EMBED_MODEL` ต้องลบ `rag.db` แล้วอัปโหลดใหม่ทั้งหมด เพราะเวกเตอร์คนละโมเดลอยู่คนละปริภูมิ เอามาเทียบกันจะได้ตัวเลขที่ดูสมเหตุสมผลแต่ผลลัพธ์มั่ว โปรแกรมจำชื่อโมเดลที่ใช้สร้าง index ไว้และจะปฏิเสธการอัปโหลดถ้าไม่ตรง ส่วน `CHUNK_SIZE` กับ `TOP_K` เปลี่ยนแล้วมีผลกับไฟล์ที่อัปโหลดใหม่เท่านั้น ของเก่าไม่เปลี่ยนตาม

## ปัญหาที่พบบ่อย

**ขึ้นว่าไม่พบข้อความในไฟล์นี้**

เป็น PDF สแกนที่มีแต่ภาพ ต้องทำ OCR ก่อน

```bash
ocrmypdf -l tha+eng input.pdf output.pdf
```

**ตัวหนังสือไทยเพี้ยนเป็น `Ã Â¸`**

แก้แล้วในเวอร์ชันปัจจุบัน สาเหตุคือ OpenRouter ไม่ระบุ charset มาในส่วนหัวของ SSE ทำให้ requests ถอยไปใช้ ISO-8859-1 ตามข้อกำหนดเก่าของ HTTP ถ้ายังเจออยู่แสดงว่าใช้ไฟล์เวอร์ชันเก่า ให้เช็คว่ามีบรรทัด `r.encoding = "utf-8"` ในฟังก์ชัน `stream_chat`

**401 หรือ No auth credentials found**

คีย์ไม่ถูกอ่าน ดูบรรทัด `env file:` ตอนสตาร์ทว่าชี้ไปไฟล์ที่ถูกต้องไหม โปรแกรมหา `.env` จากไดเรกทอรีที่รันก่อน แล้วค่อยหาข้าง ๆ สคริปต์

**402 หรือ Insufficient credits**

เครดิต OpenRouter หมด เติมที่หน้า credits ข้อความจะโผล่ท้ายคำตอบเพราะดักไว้แล้ว

**429 หรือรอนาน**

ชน rate limit โปรแกรม retry ให้เองสูงสุด 4 ครั้งแบบถอยห่างขึ้นเรื่อย ๆ ถ้ายังไม่ผ่านให้ลดขนาดไฟล์ที่อัปโหลดต่อครั้ง

**ตารางในเอกสารอ่านออกมาแล้วคอลัมน์เละ**

เป็นข้อจำกัดของการดึงข้อความจาก PDF ถ้าเอกสารเป็นตารางสเปกเยอะ ควรเปลี่ยนไปใช้ `pdfplumber.extract_tables()` แล้วแปลงเป็นตาราง markdown ก่อนเข้าขั้นตอนตัดก้อน

## ข้อจำกัดที่ควรรู้

- ค้นด้วยเวกเตอร์อย่างเดียว ยังไม่มีการค้นแบบคำต่อคำ ถ้าต้องค้นรหัสชิ้นงานหรือหมายเลขพาร์ตที่ต้องตรงเป๊ะ ควรเติม BM25 แล้วรวมคะแนนสองแบบเข้าด้วยกัน
- index อยู่ในหน่วยความจำทั้งก้อน เหมาะกับหลักหมื่นก้อน เกินจากนั้นควรย้ายไป FAISS หรือ pgvector
- เนื้อหาเอกสารถูกส่งออกไปที่ OpenRouter ถ้าเป็นเอกสารลับให้ตั้ง `EMBED_BACKEND=local` และเลือกโมเดลตอบที่รันเองได้

## นำขึ้นเซิร์ฟเวอร์

เซิร์ฟเวอร์ที่มากับ Flask ใช้สำหรับพัฒนาเท่านั้น ถ้าจะให้คนอื่นใช้ด้วย

```bash
pip install gunicorn
gunicorn -w 1 --threads 8 -t 300 -b 0.0.0.0:8000 uncle-rag:app
```

ต้องใช้ worker เดียวเท่านั้น เพราะแต่ละ worker ถือสำเนา index ของตัวเองในหน่วยความจำ ถ้าเปิดหลาย worker แล้วมีคนอัปโหลดไฟล์ worker อื่นจะมองไม่เห็นจนกว่าจะรีสตาร์ท ให้เพิ่มจำนวน thread แทน และตั้ง timeout ยาวหน่อยเพราะคำตอบเป็นการสตรีมที่กินเวลา

ถ้าวางหลัง nginx ต้องปิด buffering ไม่งั้นคำตอบจะไม่ทยอยออกมาแต่จะโผล่ทีเดียวตอนจบ

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_buffering off;
    proxy_read_timeout 300s;
}
```
