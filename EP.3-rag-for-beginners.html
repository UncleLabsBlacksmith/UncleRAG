RAG = WHAT?

คำว่า RAG ย่อมาจากอะไร?

R = Retrieval

“ค้นหา” ข้อมูลที่เกี่ยวข้องกับคำถามจากเอกสารหรือฐานความรู้

A = Augmented

“เติมข้อมูลให้” LLM ก่อนตอบ เหมือนยื่นโพยหรือหน้าหนังสือที่เกี่ยวข้องให้ดู

G = Generation

“สร้างคำตอบ” โดยให้ LLM อ่านข้อมูลที่ค้นมาแล้วเรียบเรียงเป็นภาษาคน

สูตรจำง่าย: RAG = ค้นหา → เอาข้อมูลมาให้ AI อ่าน → แล้วค่อยตอบ

02
The Problem

ก่อนรู้จัก RAG ให้เข้าใจปัญหาก่อน

LLM เหมือน คนเก่งที่อ่านหนังสือมาเยอะ แต่ไม่ได้ถือเอกสารของบริษัทเราอยู่ในมือ

📚 ความรู้ทั่วไป

มีเยอะ แต่ไม่ได้ครอบคลุมข้อมูลเฉพาะของเราเสมอ

🕒 ข้อมูลเปลี่ยนได้

คู่มือ ราคา ขั้นตอน หรือข้อมูลภายในอาจอัปเดต

🎲 อาจเดา

ถ้าไม่มีข้อมูลพอ LLM อาจตอบดูน่าเชื่อแต่ผิด

คำศัพท์: Hallucination = AI สร้างคำตอบที่ดูจริง แต่ข้อมูลอาจไม่จริง

Chunk Size

Chunk เล็ก/ใหญ่เกินไป มีผลอย่างไร?

เล็กเกินไป

เจอคำตรง แต่บริบทขาด เช่น รู้ว่า “220°C” แต่ไม่รู้ว่าใช้กับวัสดุอะไร

พอดี

ใหญ่เกินไป

08
Chunk Overlap

Overlap = ให้บัตรคำ “เหลื่อมกัน” เล็กน้อย

Chunk 1: …วิธีเปลี่ยน Nozzle และข้อควรระวัง
Chunk 2: ข้อควรระวัง + การทดสอบหลังเปลี่ยน

เหมือนถ่ายรูปพาโนรามา: แต่ละภาพต้องทับกันนิดหนึ่ง เพื่อไม่ให้ข้อมูลตรงรอยต่อหายไป

09
Embedding · Key Concept

Embedding = “เครื่องสร้างพิกัดความหมาย”

ข้อความเข้า

“รถยนต์”

“automobile”

“กล้วยทอด”

Embedding Model แปลงเป็น

รถยนต์ → [ 0.12, -0.44, 0.91, ... ]\nautomobile → [ 0.11, -0.42, 0.89, ... ]\nกล้วยทอด → [-0.72, 0.18,-0.05, ... ]

เปรียบเทียบ: Embedding เหมือน “เครื่อง GPS ที่อ่านชื่อสถานที่แล้วคำนวณพิกัดให้”
10
Vector

Vector = “พิกัด” ที่ Embedding สร้างออกมา

Embedding คือ กระบวนการหา GPS
Vector คือ ค่าพิกัดที่ได้

ในงานจริง Vector อาจมีหลายร้อยหรือหลายพันมิติ จึงไม่ใช่แค่ latitude / longitude 2 ค่า

เปรียบเทียบ

📍 “สยาม” → Lat/Long

🧠 “วิธีแก้ Nozzle อุดตัน” → Vector

ทั้งสองอย่างคือ พิกัด แต่คนละชนิดของแผนที่

11
Vector Space

Vector Space = “แผนที่ของความหมาย”

คำที่ความหมายคล้ายกันจะถูกวางไว้ ใกล้กัน

รถยนต์ ↔ automobileใกล้
รถยนต์ ↔ รถใกล้
รถยนต์ ↔ กล้วยทอดไกล

ภาพนี้เป็นการย่อให้เหลือ 2 มิติเพื่อสอนแนวคิด

12
Vector Database

Vector Database = “GPS Search ของแผนที่ความหมาย”

GPS ไม่ได้แค่เก็บพิกัด — มันช่วย ค้นสถานที่ใกล้เคียง

Vector DB ก็เหมือนกัน

เก็บ Vector + ข้อความ + Metadata แล้วค้นว่า “Vector ไหนอยู่ใกล้คำถามที่สุด”

Semantic Search

Keyword Search vs Semantic Search

🔤 Keyword Search

มองหาคำที่ตรงกัน

เอกสาร: “Nozzle อุดตัน”

🧠 Semantic Search

มองหาความหมายที่ใกล้กัน

ถาม: “หัวพิมพ์ตัน”

เอกสาร: “Nozzle อุดตัน”

มีโอกาสหาเจอ เพราะความหมายใกล้กัน

Retrieval

หน้าที่ของ Retrieval ไม่ใช่ตอบคำถาม แต่คือ หา Context ที่ดีที่สุด ให้ LLM

RAG เก่งแค่ไหน ขึ้นกับว่า “หยิบข้อมูลถูกชิ้นไหม” มากพอ ๆ กับความเก่งของ LLM

Context

RAG vs Fine-tuning vs Agent

3 อย่างนี้ไม่ใช่เรื่องเดียวกัน

RAG

“เปิดหนังสือก่อนตอบ” เหมาะกับความรู้ที่เปลี่ยนได้และเอกสารของเรา

Fine-tuning

“ฝึกพฤติกรรม/รูปแบบเพิ่ม” ปรับโมเดลด้วยตัวอย่าง ไม่ใช่ฐานข้อมูลค้นเอกสาร

Agent

“ผู้จัดการที่เลือกเครื่องมือ” อาจเลือก RAG, Web, API หรือ Database ตามโจทย์
